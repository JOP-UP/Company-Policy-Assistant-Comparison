What the benchmark shows

The rules-based method was extremely fast and used no LLM tokens, but it selected the wrong policy for the semantic question about working from Spain for three weeks. The LLM-only and LLM-with-vector approaches handled all four validated questions correctly, including the unsupported dog-in-office question. The LLM-only method required the complete 98-policy database in every prompt, producing an average of about 3,512 tokens per question, while the vector approach supplied only the top three retrieved policies and averaged about 350 LLM tokens.

The LLM-with-vector approach is preferred because it maintained the same observed answer quality as the LLM-only method while reducing average LLM token usage by about 90% and average LLM response time by about 21%. The rules-based approach remains useful as a cheap deterministic baseline, but its dependence on literal terms and manually defined synonyms makes it less reliable for paraphrased questions. No unsupported answer was observed in this four-question benchmark, so a larger test set would be needed before making a strong claim about hallucination frequency.

Methodology

How the methods differ

01

Rules-based

Question → keyword and synonym scoring → highest-scoring policy → exact policy text.

02

LLM only

Question + all 98 policies → LLM → answer and relevant policy.

03

LLM + Vector

Question embedding → top 3 semantic matches → question + retrieved policies → LLM.

Benchmark note: Four valid questions were available across the supplied LLM runs. One vector run contained a shell command instead of a policy question and was excluded. The block labelled “Rules based results” in the supplied console output duplicated the LLM-only results, so the rules-based outputs shown here were reproduced with the previously defined deterministic rules baseline against the same 98-policy CSV. Rules-based runtime is therefore a local Python benchmark; LLM and vector timings are the supplied API-call measurements.
